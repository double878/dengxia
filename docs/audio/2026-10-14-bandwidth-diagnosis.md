# 唱腔听感诊断：6 kHz 带宽天花板

日期：2026-10-14。状态：**已定位一个可量化、可复现的根因候选——素材带宽。尚未做任何换源或重生成，未修改运行代码与正式素材。本条不能替代用户听验。**

用户提出「AI 生成的唱腔不自然、有机器感和电音」，并再度提交参考视频，询问是否应放弃唱腔。本记录只回答「电音/机器感的物理来源可能是什么」，不判定唱腔路线的存废。

## 结论摘要

- 用户本次提交的视频与仓库内既有文件**逐字节相同**，不是新素材，见下节。
- 该参考的音频在 8 kHz 以上仍有 **0.96%** 能量、-60 dB 截止于 **14268 Hz**；游戏内**全部** AI 生成音频在 8 kHz 以上的能量是 **0.0000%**，-60 dB 截止集中在 **6.5–7.6 kHz**。差距约 49 dB。
- 上限不是模型造成的。损失点在最上游的音源获取：第一关与第二关采用的央视网源音频流是 **AAC 29 kb/s、480×270** 的低清档，实测带宽上限 **6107 / 6063 Hz**；喂给模型的工作参考 `duet-continuous-reference.wav` 本身已是 **6060 Hz / 0% >8 kHz**。
- 对照：项目已持有的 B 站源 `乐亭白蛇传_第一集_原始参考.m4a` 为 **AAC 104 kb/s**，带宽 **12356 Hz / 0.95% >8 kHz**，未受此影响。
- 这与既有听验记录方向一致：唯一通过听验的唱腔实验（2026-10-10 乐亭单句）使用 B 站全带宽源；正式制作改用央视网源之后才出现「电音感」类反馈。该一致性是相关性，不是已证明的因果；需要用换源重生成来验证。

## 排除的假设

自查了「音高被量化成十二平均律」这一常见的电音成因。以自相关法提取 F0 后统计：落在某一半音 ±10 音分内的有声帧占比，参考 29.0%，乐亭单句模型输出 18.1%，央视双语纯人声 14.1%，央视参考人声 19.8%；相邻帧 F0 跳变中位数 4–6 音分（两帧间隔 5.33 ms）。**没有出现自动调音式的音高栅格化，也未见过度平滑。** 该测量在带锣鼓的混合素材上粗略，只能说明未发现量化证据，不足以排除其他音高层面的问题。

同理，既有记录中已排除的后期效果、拼接改音与 PCM 饱和（`speech-diagnosis.json`，最大偏差不超过 1/32768）与本条不冲突。

## 建议修法（按性价比排序，均未实施）

1. **换源，不换模型。** 把唱腔参考从央视网 29 kb/s 档换成全带宽源。首选项目已持有的 B 站 `乐亭白蛇传_第一集_原始参考.m4a`（104 kb/s，已通过单句听验）；若必须保留京剧《游湖》方向，需重新抓央视的高清晰度档（1080P 档音频码率通常显著高于 29 kb/s），并在换源后复测带宽再生成。
2. **同一条链上的对白也要换。** F5-TTS + Seed-VC 的音色参考取自已判退的央视素材，`wine-duet` / `main` 同样 0% >8 kHz，换源范围应包含对白参考。
3. **参考换词的约束不变。** 只改词、不改旋律与收腔；不要在参考已被限带时改用「让模型自己发挥旋律」，那只会在带宽之外再引入第二个听感问题。
4. **若确实无法换源**，才考虑高频嫁接：模型负责 0–6 kHz，把同一时间位置上原始参考的 6–16 kHz 叠回，伴奏直接使用全带宽原录音。这是补丁，有引入新瑕疵的风险，优先级低于换源。
5. **用第三关当基准。** `act3-mountain/original.wav` 就是用户认可的那个声音，可作为校准听觉的参考轨，不作为唱腔生成的输入。
