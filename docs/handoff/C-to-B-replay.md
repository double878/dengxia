## 1. 数据流与职责边界

```
A 端逻辑            C 侧                          B 侧
─────────────      ────────────────────         ────────────────────
操控/节拍/判定  ─→  录制：读状态 → 记时间轴  ─→  画面：读状态 → 出画面
统一音乐时钟    ─→  回放：逐帧喂状态        ─→  声音：读事件 → 播音效
关卡结束条件    ─→  暂停/跳过/重看          ─→  影人/幕布/灯光/锣鼓
                  导出
```

**单向数据流**（`TECH_DESIGN.md` 2.3）：A 改状态 → C 只读 → B 只读。**B 不回调 A、不回写状态。** C 侧 `CStageRecorder` 已在代码层面守住这条边界（只读不写）。

**关键推论：C 录不到声音。** C 记录的是「状态 + 离散事件」，回放时的锣鼓与音效由 B **按时间轴重新触发**，不是录音重放。请勿按"回放=播放录制音频"设计。

## 3. C → B 输入契约（【代码确认】）

以下取自 `origin/feat-level1-controls` 的 `PuppetState.to_dict()` 与 `LampState.to_dict()`，C 侧录制与回放均按此结构读写。

### 3.1 影人状态（长度固定 3，下标即 puppet_id）

| 字段 | 类型 | 单位 / 区间 | 说明 |
|---|---|---|---|
| `puppet_id` | int | 0–2 | **下标即 id**，不查找 |
| `stage_pos` | Dictionary | `x`/`y` 归一化 0–1 | 接地点在幕布中的位置 |
| `stance` | float | 0.0–1.0 | ⚠ **0.0 = 完全站立，1.0 = 完全蹲下** |
| `facing` | float | −1.0 – +1.0 | −1.0 面向左，0.0 正面，+1.0 面向右 |
| `turn_progress` | float | 0.0–1.0 | = `abs(facing)`，转身过渡完成度 |
| `hand_angle` | Dictionary | **弧度** −0.6 – +0.6 | `left` / `right`，**x=左手 y=右手** |
| `head_id` | int | −1 或 0–5 | −1 未分配；3 初始头 + 3 备用头 |
| `hook_slot` | int | −1 或 0–1 | −1 未挂起；两个挂钩槽位 |
| `is_controlled` | bool | — | 当前是否被玩家操控 |

**给 B 的三个易错点**：
1. `stance` 方向容易反 —— 0 是站立，不是蹲。
2. `hand_angle` 是**弧度不是角度**，范围仅 ±0.6（±34°），不是 0–360。
3. `head_id` / `hook_slot` 的 **−1 是「无」不是「第一个」**。

### 3.2 油灯状态（4 字段全部 0.0–1.0）

| 字段 | 说明 |
|---|---|
| `distance` | ⚠ **越大表示灯离影人越近**，不是普通距离 |
| `exposure` | 显露度（倾灯） |
| `oil` | 剩余灯油比例，只由歌曲时间消耗，**不可回升、不可 <0** |
| `flame_feedback` | 合拍驱动的火焰反馈强度，连续量 |

### 3.3 歌曲时间

唯一时钟读数：`int get_song_time_ms()`。
- **禁止**使用 `Time.get_ticks_msec()` 或任何墙钟。
- 暂停时读数**冻结**，恢复后从冻结值继续（不漂移）。

---

## 4. 暂停 / 恢复语义（易错，需严格遵守）

暂停期间 A 端 `tick()` **开头即 return**，因此：**不推进状态、不产出新事件、歌曲时间冻结。**

B 侧对应行为：
- 动画**停在当前帧**，不得用 `delta` 继续累加动画计时。
- 音效停止或淡出；锣鼓循环暂停。
- 恢复后从冻结处继续，**不重置**动画起始时间。
- 判据：只要 C 传给 B 的 `get_song_time_ms()` 未变，就是暂停态。B 不要自己另算时间。

## 7. 三个必须先拍板的卡点

这三个不定 C 无法开工回放，请优先答复。

### ① 幕前画面由谁实现？

C 在回放时**只提供状态，不生成画面**。若 B 只实现幕后，**回放将没有画面**。
→ 请确认 B 覆盖范围是否包含幕前视角（`TECH_DESIGN.md` 2.1 要求幕前用透色镂空正面贴图、舞台横坐标镜像）。

### ② 影人是分件旋转还是单张整图？

回放要求 **1:1 重演而非播动画**，画面必须由状态驱动，因此需要知道：
- 分件（头 / 身体 / 左右手各自贴图 + 枢轴）还是单张整图？
- 若是分件，**枢轴坐标放配置文件还是由 B 提供**？
  C 倾向：放配置，这样换图不改代码。

### ③ 能否先给一组占位资源？

**当前仓库零贴图、零音频**（无 `assets/`、无 `textures/`、无任何 png/svg）。后果：回放流程**无法端到端跑通**，C 的插值与镜像逻辑也无法验证。

→ 建议先给**最简占位资源**（纯色剪影、临时锣鼓循环均可，**不需要正式稿**），C 即可完成回放验证，不必等正式美术。

## 8. 附：幕前镜像的实现归属（供讨论，非结论）

`TECH_DESIGN.md` 2.1 写明幕前视角要"把舞台横坐标镜像并切换朝向素材"。

**C 建议**：横坐标镜像由 B 在渲染层处理（`scale.x = -1`），C 不做坐标变换。
**理由**：C 侧只提供归一化状态，坐标变换属表现层职责。

**但需 B 判断**：分件枢轴在 `scale.x = -1` 下旋转方向会翻转 —— **枢轴算错会导致手部镜像错位**。这一条 B 更清楚实现细节，请 B 定夺并告知 C 是否需要配合。
