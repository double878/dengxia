# 第二关第一幕布景接入与主干合并计划

**目标：** 将 `feat-act2` 的法海、操作手和两关衔接合入 `main`，正式第二关第一幕使用队友 PR #9 的门楼、菊石和柳树。

**边界：** 复用 Godot 4.7.2 和 `CStageBinding`，不修改队友布景构图、不加入尚未制作的对白和剧情。遵照用户要求由当前代理直接实施，不使用子智能体。

## 切片与验收

1. 拉取最新 `origin/main`，合入 `feat-act2`，解决代码格式归一化与队友增量的交叉点，保留双方行为。
2. 扩展 `tests/c/run_act2_opening.gd`：验证三种收场路径均进入包含第二关布景的独立开场；检查布景编号、三件资源、层级、幕布裁剪、人物地面与控签操作。先观察新增检查失败。
3. 在 `scripts/act2/act2_opening.gd` 挂载 `CStageBinding(stage_id=2)`，关闭第一关的雨幕，按第二关布景接地线设置人物脚点；保持数字键上场、空格接手和操作手拖签。
4. 先解析改动脚本，运行定向无头与 Windows 窗口回归并检查截图，再执行现有 A/B/C 相关套件及导入、启动、导出门禁。更新 PRD、TECH_DESIGN 和交付记录，准确记录验证范围与局限。
5. 检查 diff，仅提交接入相关内容并推送 `feat-act2`；创建面向 `main` 的 PR，按用户明确授权 squash 合并。更新本地 `main`，确认远端主干包含法海、操作手、两关衔接和队友布景。

**依赖顺序：** 最新主干资源 → 正式场景挂载 → 功能/发布验证 → PR squash 合并 → 本地主干同步。各独立检查可以并行；共享仓库合并与编辑顺序执行。
