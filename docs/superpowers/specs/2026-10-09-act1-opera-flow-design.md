## 1. 本轮确认的目标

依据本轮两组回答 `BABAA`、`AAA`：

- 开场小青与白素贞有可听见的戏曲念白，没有连续背景音乐。
- 白素贞移步时有配乐；到许仙身旁后，器乐衔接男女借伞唱段。
- 采用已批准的新词与京剧角色表达方向，制作新的唱念录音与匹配伴奏；字幕必须对应实际唱出的内容。原演出只作为风格与人物表达参考，具体音色和生成效果必须试听确认。
- 唱句完整结束后开放接伞。两手满足条件、伞实际换手时，触发一次重音并收住此前伴奏。该重音是交接反馈，不以预设拍点考玩家。
- 随后换另一段器乐，玩家持伞走回小青身旁，再返回许仙处还伞；沿用同一幕布、同一布景。
- 还伞后采用含蓄的戏曲念白，以感谢、不舍或相约表达爱慕，不新增第二处必须演唱的对白。
- 器乐可以在段落交接处有限等待玩家；念白、唱句不循环、不按拖动速度变速。
- 不再沿用正常演出 55 秒、上限 60 秒的要求。长度由可用乐句和操作余裕确定。
- 超时属于少见兜底：保持实际道具归属，跳过依赖未完成动作的对白，继续器乐收尾；不自动代演。

成功标准是实际听见、看见以下因果：念白结束，配乐起，玩家移步，到位入唱，唱段收腔，两手交接，重音落下，旧乐停止，新乐游湖，实际还伞，念白传情。

## 3. 推荐音频接法

采用“分段制作、离线编排基础音轨、等待时播放独立器乐循环”。

基础音轨包含正常路线的念白、器乐、唱段、游湖器乐、还伞念白和结尾，预先打磨其衔接。主轨关闭循环，始终由同一个 `MusicClock` 驱动。借伞重音独立导出为一次性短音频，基础轨中不重复放入这个重音：只有实际交接事件才能触发它，避免音频缓冲已越过暂停接点而提前响锣。

在指定交接点，主轨与歌曲时间停住；独立辅播放器接入该点的器乐过门。玩家满足条件后，在已制作好的出口交回主轨，从原位置续播。等待不是再次演唱，也不是重新启动本幕。

入唱与返程念白入口前保留无字头的器乐保护区，冻结点位于保护区起点，不能紧贴人声第一采样。保护区长度必须覆盖演示机的音频输出缓存与帧调度余裕，经实际声卡测量后写入配置。到位后才允许主轨越过保护区，辅轨承接这段保护区的音乐。这样才不会在主轨暂停生效前，由已经送入声卡的音频缓冲提前漏出对白。

这比运行时逐句切换主播放器更适合当前工程：不需要为每段重置时钟，也不需要在主轨循环回绕时推算歌曲时间。基础轨从源码角度仍是固定编排，但实际演出允许在指定器乐节点延长，取代旧“所有段落绝不重复”的约定。

第一版使用新词的新录音。生成或录制能提供真实分轨时可使用现有同步能力；仅有混合录音时不制造虚假的人声轨、伴奏轨或五个副本。混合素材不得再叠一条同内容伴奏，也不能把原词演出人声登记为改写成品。

混合素材无法独立改变人声音量。对白期间不安排新的评分动作；低合拍反馈主要由现有火苗与补救提示承担，不把全混合轨降音量声称为“只让唱腔转弱”。若正式版仍要求人声与锣鼓独立控制，必须取得独立轨并另行试听验收。

## 4. 正常段落与转移条件

| 阶段 | 声音 | 操演与转移条件 |
| --- | --- | --- |
| `opening` | 小青、白素贞念白，无连续配乐 | 短序幕先建立人物关系；念白结束，起移步器乐并开放主移动教学 |
| `approach` | 第一段器乐及入唱引子 | 白素贞走向许仙；位置判断复用 `in_join_window()`，不要求先抬手 |
| `wait_arrival` | 与引子匹配的纯器乐过门 | 到入唱点仍未到位才进入；保持移步可操作，最多等待 8 秒 |
| `borrow_dialogue` | 完整男女唱段及配套伴奏 | 到位后在最近的已标注乐句接点入唱；提前到位不截断正在播放的引子；不开放伞的换手 |
| `wait_take` | 短器乐接伞过门 | 唱句与拖腔播完后开放交接；手位满足条件即换伞；最多等待 8 秒 |
| `take_close` | 一次接伞重音、旧伴奏收住 | 由实际 `umbrella_take` 触发独立收锣；取消等待循环并交回基础轨；基础轨不含第二次同样重音 |
| `tour` | 第二段器乐 | 玩家持伞走到小青身旁，再回来；保留现有折返点与返回方向判据 |
| `wait_return` | 游湖音乐的短器乐过门 | 到念白入口仍未还伞才等待，最多 8 秒；还伞不要求重新抬手 |
| `return_dialogue` | 含蓄的感谢、相约念白 | 必须已有实际 `umbrella_return`；提前还伞则到安全乐句接点进入，不重播游湖段 |
| `closing` | 短器乐收束、完整尾响 | 玩家放手收势，音频收束后正常结束本幕 |

“开放主移动教学”是本方案的实施建议：开场保留可看见的短念白序幕，结束立即起乐并允许横移，避免玩家已在移步而开场仍无伴奏。保持幕后视角，不新增幕前过场或自动移动。

接伞许可开放时重新检查当下手位。如果玩家在唱段期间抬手，随后又放下，不能因曾经到位而自动接伞。若许可开放时仍相接，可立即交接，不强迫玩家再抬一次手。

游湖音乐入口紧跟接伞收锣编排，避免长静音；用第二段的轻起音让重音攻击先被听见，随后器乐展开。若玩家立即离开接伞区，第二段配乐应随移步进入，重音自然余响可以保留。制作样段必须覆盖这一情况，不能用额外操作锁补偿音频衔接。

借伞只在当前剧情节点完成一次。还伞后不自动重新开放接伞，避免原控制器允许的多次往返触发第二次收锣或倒退剧情。

当前按已批准的改写报告制作新录音，以京剧《游湖》的初遇、借伞与答谢动机作为剧情参考。先试白素贞两句，再试许仙答句；用户确认新词和戏曲感后，制作六句连续唱段、开场念白和还伞念白。公开演出供人物与声腔比较，不能将未经听辨的片段标成已验证音色。

早期乐亭参考与失败试验继续保留追溯：

- 来源：`https://www.bilibili.com/video/BV1xX4y1Y7sJ/`。
- 已登记的第一集原始音轨：`builds/real-performance-reference/乐亭白蛇传_第一集_原始参考.m4a`；本轮核对文件存在，未重新试听或全量解码。
- 已有 5:50–6:40 参考的画面字幕指向求取灵芝草。它不是已确认的借伞唱段，不能沿用原词充当本关对白。
- MiniMax 参考翻唱因失去目标戏曲感觉被用户拒绝；ACE-Step 局部改词也已根据用户“感觉跟原曲一摸一样，似乎并没有什么改动”的试听反馈判退。两份失败材料保留追溯，不进入正式包，不作为已可用的改词路线。

制作顺序：先确认新词实际可听清且角色戏曲感合意，再打磨连续的器乐—唱段关系。借伞前的唱词表达邀请、相助或借伞意愿，不提前宣告玩家已经拿到伞。

不能用盗仙草唱词、无关称谓或相反情绪凑成借伞对白。若生成服务不可用或小样未通过，明确记录阻断原因；同一问题最多两次有明确原因的尝试，不批量试错或将数值检查冒称声音效果通过。

开场、还伞念白使用已批准的新台词，保持与唱段协调的角色声音。普通朗读加混响不能作为戏曲味验收通过依据；开场新录音不含连续配乐，不预先承诺分离工具一定能从混合音轨取得干净念白。

每条素材登记 `asset_id`、生成或录制来源、参考链接、实际台词、角色、完整参数及可核实的模型/种子、完整解码结果、SHA-256、采样率、声道、增益处理、使用权状态、试听结论。外部截取素材另记源分集与起止毫秒。运行素材统一 48 kHz / 16-bit WAV，主轨不循环；循环边界由辅播放器配置管理。

过门必须是真正无唱词的器乐，不靠剪掉字头保留残余歌声。切点取完整乐句、收腔及尾响；渐变只能修复切点，不能修复声腔、调性和录音声场不一致。BPM、鼓点和接点由音源确认，不将旧 96 BPM 视为原演出事实。

先制作一段“移步器乐 → 借伞唱段 → 接伞过门 → 重音止乐 → 第二段器乐入口”的可听样段，同时听即时接伞和延迟接伞两版。通过后再补首尾念白并确定长度。

## 6. 时间、等待与兜底

- 正常路线长度等于制作后的基础轨长度；不预先填写未经音源支持的精确秒数。
- 歌曲时间只读 `MusicClock.get_song_time_ms()`；等待与补救冻结它，灯油也停住。
- 等待超时只读 `MusicClock.get_real_time_ms()`，菜单暂停连这条时间也冻结。
- 每个等待点最多一次、最多 8 秒。相同未完成动作不再额外开启一轮 8 秒补救；帮助结束后必须退出该等待。
- 等待是 `waiting`，补救是 `remedy`。等待器乐保持原音乐的节奏，补救使用原有半速慢鼓；不能因读取到歌曲时间冻结就把等待误当作补救。
- 冻结由 `StageDirector` 统一计算：`waiting_open OR remedy_open`。不能让音频模块和补救模块各自解除同一个冻结标志。
- 器乐安全出口需在素材配置中显式标注。不得为了等完整循环而突破 8 秒上限；硬截止使用预制短收束及必要的防爆音释放。
- 本关改用音源实际锣鼓节点编排剩余评分动作。自由交接的借伞、还伞不再继续使用旧固定拍点产生错拍；等待期间不生成新的拍点评分。

兜底只设一个无对白的器乐收尾，不制作另一套复杂剧情。三个等待点任一超时，禁用尚未成立的交接对白，保持伞的真实归属，进入器乐收尾供玩家继续操演后正常结束。没有实际借伞就不凭空生成伞，没有实际还伞就不播放已奉还的感谢对白。

若兜底需跳过基础轨区间，不能调用现有 `seek_ms()`，因为它调用 `start()` 并重置真实时间。应增加保持双时钟语义的前向跳段操作，同时记录跳过的段落与 Cue，防止被跳过的旧落点一起触发漏做。其他关卡原有重开/seek 行为不改变。

## 7. 模块与事件职责

| 文件/模块 | 最小改动职责 |
| --- | --- |
| `scripts/a/stage_def.gd` | 第一关版本选择、素材标注的段落与 Cue；其他关卡数据保持原行为 |
| 新 `scripts/a/level1_opera_flow.gd` | 第一关段落状态、到位/接伞/还伞条件、等待截止与一次性转移；不自行计时、不直接播放音频 |
| `scripts/a/stage_director.gd` | 在现有演出推进中接入新流程、统一冻结、激活当前 Cue、收场 |
| `scripts/a/umbrella_controller.gd` | 由第一关流程控制交接许可，保留手距、手高、折返点与方向判据 |
| `scripts/a/music_clock.gd` | 保留唯一双时钟；只为前向跳段补充保持真实时间的接口 |
| `scripts/b/audio_score.gd` | 支持混合基础轨、等待过门、接点、念白/唱句类型及来源校验 |
| `scripts/b/performance_audio.gd` | 主轨/等待轨/独立收锣/慢鼓播放与暂停、事件驱动交接、字幕；不重新判定动作 |
| `scripts/a_test/level1_harness.gd`、`level1_a_scene.gd` | 接入第一关新版音频与状态，停用临时节拍，显示动作线索与字幕 |
| 录制/回放消费者 | 原样记录和执行段落、等待、交接、跳段与音频版本；不重新评分 |

沿用事件外壳 `time_ms / kind / object_id / cue_id / payload`。新增事件的载荷包含 `real_time_ms`、`phase_id`、`audio_version`、`asset_id` 和出口侧统一分配的单调 `sequence`：

- `opera_phase_changed`：阶段、进入原因、基础轨位置。
- `opera_wait_begin` / `opera_wait_end`：等待原因、截止时间、实际等待长度、退出原因。
- `opera_score_skipped`：基础轨跳转前后位置、被跳过的阶段与 Cue。
- 复用 `umbrella_take` / `umbrella_return`：只有真实交接才有对应事件。
- 复用 `dialogue_line_changed` / `audio_state_changed`：附对白类型与新版素材版本。

事件由宿主合并后统一排序编号，不能让 A/B 分别从零计数形成同时间重复序号。回放连续样本也必须保存真实时间：等待期间歌曲时间不动，但玩家仍然在移动；只有等待起止事件不足以恢复这些动作。

回放按同一演出的真实时间顺序应用样本和事件，记录中的歌曲时间用于主轨定位。需保留真实等待长度和跳段，不重新推算“这次走到位置就入唱”，也不再次寻找新的音源。

## 8. 验收与执行边界

先做声音，再做接入，每次完成一个可验证切片。正式验收覆盖：

1. 开场确有戏曲念白、无连续配乐；移步始终有配乐。
2. 快到位、慢到位均能自然入唱，没有重复唱句、残余人声或双重伴奏。
3. 唱段期间不能提前接走伞；唱段结束仍相接则可立即接伞；放下手则不能凭历史到位接伞。
4. 借伞实际发生与重音听见/换手看见一致，重音只响一次，旧伴奏收住。实际声卡延迟需 Windows 试听/录屏测量，无头断言不证明可听同步。
5. 立即持伞离开和稍作停留都能进入第二段音乐，没有移动期间的意外静音。
6. 往返条件仍有效；没有走到小青身旁不能原地还伞；还伞后的念白仅在真实还伞后播放。
7. 在念白字头、拖腔、等待、收锣尾响中暂停/恢复，没有重唱、丢尾或重音重复。
8. 8 秒超时只发生一次，不叠加补救，不伪造道具归属，仍能收场。
9. 重开清空许可、等待、事件与所有播放器；退出不留下循环声。
10. 完整回放保留等待中的动作、声音顺序和真实时长；未接入实际 Recorder/Replay 时必须标注未验收。
