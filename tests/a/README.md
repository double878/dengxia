# A 范围测试说明（第一关操控与关卡逻辑）

工具链统一为 Godot `4.7.2.stable.official.ed1daf0bf`。以下命令都假设在仓库根目录执行，
`godot.exe` 取本机同一版本路径（示例为 `D:\Godot\4.7.2\godot.exe`）。

## 1. 无头行为测试（回归门禁，退出码 0/1）

```powershell
& 'D:\Godot\4.7.2\godot.exe' --headless --path . --script res://tests/a/run_tests.gd
```

切片 1-4 共 56 条用例；断言总数以测试运行输出为准（当前 1056 条）：

- **切片 1（操控，16 条）**：初始不变量、胸签命中、横向与纵向拖动及两端截断、
  **翻面为二值正/反两面且 0.1 秒完成、不瞬间跳变**、双手独立与双手同动、按住连续/松开保持、
  相反指令保持姿势、**连续量边界（双手可到达 180°）**、`TimedEvent` 契约与取走即清空、
  状态先于事件、同帧松开结算位移、暂停时丢弃操控输入、空格的挂起与取回保留姿势、
  换头是交换而非复制、**空格提示按挂钩的实际可用性说话（满槽时不显示「空格 = 挂起」）**。
- **切片 2（音乐时钟与关卡时长，11 条）**：自由计时单调推进、暂停冻结（含拍序号
  与跨拍报告）、恢复不跳变、跨拍每拍只报一次且序号连续、`beat_time_ms` 与
  `get_beat_index` 互逆、第一关 35000 ms / 56 拍 / 校验通过、校验能报出未覆盖与
  `cue_id` 重复与落点越界、操控事件时间戳等于 `MusicClock` 读数、缺音轨时明确降级。
- **切片 3（关键动作判定，14 条）**：动作表覆盖站起/左右移动/抬手/重音落点、
  站起与蹲下的范围方向相反、每条线索在落点前准时可见且载荷齐备、窗内命中并记录
  偏移、窗外动作照常发生但记未命中、容差可配置且改变判定边界、20 帧持续平移只
  判定一次、到位需「先离开范围再进入」且站定不动不算、`cue_*` 事件契约、
  未做的关键动作保持待判定、线索不泄露评分/容差/精确拍号；持续按键进入抬手范围、
  已面向左时再次左移、提前错拍后在判定窗内重做、松开当帧结算到位。
- **切片 4（补救与收场，15 条）**：空场跑完与全命中的正反两面、漏做开窗、
  **两条窗口并存时的示范优先级与「还有窗口就继续冻结」**、错拍不重复开窗、
  补做成功、**8 秒按真实时间超时**、同一错误不刷窗口、
  **菜单暂停连真实时间与补救倒计时一起冻结**、35 秒整点结束、
  **收场时开着的窗口随演出结束关闭并解冻**、同屏唯一示范与各自留记录、
  低合拍触发补救、畸形输入安全失败、
  **补救冻结只停歌曲时间/拍点（真实时间与 8 秒倒计时照走）**。

## 2. 图形环境脚本化实测（真实窗口，退出码 0/1）

```powershell
& 'D:\Godot\4.7.2\godot.exe' --path . res://scenes/a_test/a_controls_test.tscn -- a_controls_probe
```

分三段：

- **同步段**（`controls_probe.gd`）：真实窗口里用与游玩完全相同的 `PuppetController`
  输入接口走完整链路（胸签命中 → 拖动 → 状态 → 事件），打印翻面的帧数与正/反两面切换、
  站蹲两端、双手数值（含 180° 上限）、冲突冻结、240 帧边界压力、第一关时长与数据校验。
- **判定段**（`cue_probe.gd`）：在真实渲染进程里跑关键动作判定——6 条线索的时刻、
  窗内命中（含 offset）、窗外未命中且姿势照常到位、20 帧持续平移只判定一次、
  「到位」需先离开范围再进入。时间由测试台推进，因此结果确定、不依赖帧率。
- **逐帧段**（`clock_check.gd`）：用真实墙钟做对照，测量歌曲时间推进速度（漂移）、
  暂停期间是否完全冻结、恢复后是否从冻结值继续（不跳变、不把暂停时长算进歌曲时间），
  并断言 `is_audio_driven()` 为真。

**为什么需要它：**验证者无法向运行中的窗口注入真实鼠标/键盘事件，
而「脚本能解析」不等于「操控与时钟正确」。本模式让图形环境下的可测量行为留下
可复现证据。

## 3. 人工实测（必须由人在图形环境完成）

```powershell
& 'D:\Godot\4.7.2\godot.exe' --path . res://scenes/a_test/a_controls_test.tscn
```

脚本化实测与无头测试都**不能**替代以下人工确认：

- 真实鼠标按住胸签拖动的**手感**是否跟手、身位与手指是否对得上；
- 真实键盘按住 `A`/`D`/`Shift+A`/`Shift+D`/`W`/`S` 的连续变化与松开保持，以及
  **手能不能一路抬到 180°（举过头顶）**；
- 画面上翻面是否像**一张纸片快速翻过去**（0.1 秒、压到最窄再展开），而不是缓慢旋转或跳变；
- **是否真的听见临时节拍音**（代码只能证明音频在播放、位置在正确推进）；
- 故意漏掉一个动作后，**是否听得出来**鼓点被拖慢到 0.1 倍速、时间停住，画面是否明确标出
  「补救中 · 演出已暂停」；补做成功后是否从原处继续、拍点没有漂；
- 按 `ESC`（或右上角按钮）暂停后是否**听得出**音频停住、再按一次是否从原处继续
  而没有重复拍子。**暂停不是空格**：PRD 第 4.1 节把空格定为「挂起/取回影人」；
  另外注意暂停会连补救倒计时一起冻结，与补救冻结不是一回事；
- 在 1920×1080 目标分辨率下整台与 HUD 是否完整可见。

## 4. 第一关场景脚本化实测（真实窗口，退出码 0/1）

```powershell
& 'D:\Godot\4.7.2\godot.exe' --path . res://scenes/a_test/level1_a.tscn -- level1_a_probe
```

在真实渲染进程里用同一 `Level1Harness` 快速跑完整条第一关时间线，断言关卡时长、
关键动作数量、**开局两个挂钩槽都被布景占满**（因此本关「空格 = 挂起」不可能成功）、
暂停冻结、按时收场、各类事件产出，以及**补救冻结的起止与「真实耗时长于歌曲时长」**。
另有 `-- diag` 可打印每 30 帧的
`fps / song / real / frozen / audio_driven / win / canvas_scale` 读数，排查卡顿、音频停摆或窗口尺寸不符时用它。

## 6. 关于音频来源

B 的正式锣鼓主音轨尚未交付。A 的测试场景用 `scripts/a_test/metronome.gd` 现场合成
节拍音（`AudioStreamGenerator`），不引用任何素材文件、不改 B 的正式音频目录。
补救期间那路「0.1 倍速慢鼓」同样是占位：它由同一套合成内容按 0.1 倍速、4 拍一循环播放，
主音轨则在冻结期间真的暂停（解冻后从同一拍点续上）。
拿到正式音轨后必须复测时钟、拍点对齐与慢鼓音色，在复测之前不得宣称「已与正式音轨对齐」。
